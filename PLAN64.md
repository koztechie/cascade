## Відкладені рішення (щоб не перепитувати)

- **M3 — живий WASM-вьюер: ВІДКЛАДЕНО до після-відео** (кроки19–28 мають
  пріоритет через дедлайн 9.12). **Форма узгоджена:** окрема сторінка
  `viewer-live.html` + ціль `make viewer-live` (піднімає локальний
  HTTP-сервер); **статичний `viewer.html` лишається основним** (подвійний
  клік, без сервера) — жодного ризику для поточного UX.
  Ключові факти з дослідження: пакет `@relate/relate-wasm` (Apache-2.0,
  0 залежностей, **6,9 MB**); **WASM не відкриває `.rl`** — лише `:memory:` /
  `opfs://`, отже граф відтворюється в браузері з `data/load.cypher`
  (1786 детермінованих структур); ES-модулі/worker/`fetch(.wasm)` **не
  працюють через `file://`** → потрібен сервер; вузол: module worker +
  `execute(stmt, params)` → wire-JSON, OPFS для сталості. Оцінка: ~півдня.
  **Відомий прогін (зафіксовано):** наш проєкт **не використовує WASM-кут**
  — це одна з «інвентивних» можливостей Relate (Creativity), але свідомий
  компроміс: місце WASM-а — після відео й подачі, якщо лишиться час.
- **M5 — markdown-vault режим магазину: ВІДКЛАДЕНО до після-відео**
  (рішення, як і M3). Результати дослідження збережені, щоб не повторювати:
  - **Допустимі кодеки:** `parquet, json, markdown, rkyv` — через
    `RELATE_SNAPSHOT_FORMAT` (середовище) або `--snapshot-format`.
  - **Структура vault:** `index.md`, `log.md`, `<Label>/<key>.md`,
    `<Label>/index.md` + `.relate/manifest.json` (`"codec": "markdown"`) + WAL.
    Це й є «папка нотаток» у стилі Hive/Trailmark/Morrow.
  - **Блокер на наших даних:** ім'я файлу береться з ключа вузла, а
    `Mapping`-вузли не мають унікального ключа →
    `storage error: markdown vault: two nodes of label Mapping share the key
    value 'gtin'; the vault filename would collide` → checkpoint падає,
    `.md` не з'являються взагалі.
  - **Обхід підтверджено пробами:** движок **віддає перевагу властивості
    `key`** — два `Mapping` з однаковим `target_field`, але різним `key`,
    проходять (`FLUSH_OK`). Тобто мінімальна зміна даних = унікальний `key`
    для `Mapping` у `generate_data.py`.
  - **Обсяг повної заміни (варіант A):** **31 файл** згадує шлях магазину
    (Makefile, усі скрипти, `.mcp.json`/`opencode.json`, доки, шаблони) +
    зміна даних + **повторна перевірка детермінізму M1 для markdown
    (невідома)** + пере-коміт store + оновлення тверджень/CI. ~день+,
    високий ризик перед дедлайном.
  - **Нота:** `.rl` теж приймає markdown-кодек (950 КБ проти 1,07 МБ у
    parquet), але тоді нотатки живуть **всередині бандла** — читабельної
    «папки» дає лише **директорія**.
  - **Варіанти на майбутнє:** A — повна заміна; **B — дешево: `make vault`**
    (експорт нотаток із `.rl`, ~1–2 год, без ризику для гейтів); C —
    відкласти (обрано). Після відео почати з B, якщо часу вистачить — A лише
    за наявності запасу.
- **M1 (байт-детермінований store), M2 (CI) і M4 (пін `relate_db`) —
  ВИКОНАНО** (коміти `fc0a691`, `60d344c`, `ab19598`): `store/catalog.rl`
  більше не «чорнить» git, CI біжить на кожен push і PR, версія движка
  пінована й охороняється `check-claims`.
